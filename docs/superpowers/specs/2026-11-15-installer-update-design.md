# 윈도 설치 파일과 업데이트 확인 — 변경 설계

## 의도
교회 PC에서 zip을 풀어 아무 데나 두는 대신 설치해서 쓰고, 새 버전이 나오면 앱이 알려 주고 버튼 한 번으로 설치까지 하게 한다. 배포는 지금처럼 드라이브 폴더(https://drive.google.com/drive/folders/16sIClrgZI2zEmbxvKF1BxcOzVhQ9OcIM).

## 하지 않는 것
맥 설치 파일·맥 자동 설치(맥은 알림 + 드라이브 폴더 열기), 코드 서명, 저절로 꺼지는 업데이트(방송 중 끊김 방지: 버튼을 눌러야만), 받은 파일 해시 검사(NSIS 설치 파일이 실행할 때 스스로 무결성 검사를 하고, 깨진 exe는 윈도가 실행하지 않음), 업데이트 확인 끄기 설정.

## 접근 방식
- 설치 파일: NSIS(`brew install makensis`, 맥에서 윈도 설치 파일을 만드는 사실상 유일한 길). Inno Setup은 wine이 필요하고, MSI(wixl)는 바로가기·제거 등록이 더 번거로움.
- 버전 확인·받기: 윈도(10 1803+)와 맥에 기본으로 있는 `curl`을 `std::process::Command`로 부른다. 새 의존성 없음. curl이 없는 옛 윈도면 확인이 조용히 실패할 뿐.
- 버전 정보: 드라이브 폴더의 `latest.txt`(파일 ID `1794QcL_4W-HXkp3ayiL_lf5Q4qpENQ-y`, 내용을 새 버전으로 바꿔도 ID 유지). 받는 주소 `https://drive.google.com/uc?export=download&id=<ID>` — 작은 텍스트와 7.5MB zip 모두 curl로 그대로 받아지는 것 확인함.

## latest.txt
```
0.3.0
https://drive.google.com/uc?export=download&id=<설치 파일 ID>
```
첫 줄 최신 버전(점으로 나눈 숫자), 둘째 줄 윈도 설치 파일 주소(https). 앞뒤 공백·CRLF·UTF-8 BOM은 무시(메모장으로 고쳐도 되게). 형식이 틀리면(드라이브가 HTML 오류 페이지를 줄 때 포함) 새 버전 없음으로 본다.

## 앱 동작
- 버전은 `Cargo.toml` 하나가 기준. 이번에 0.2.0, 배포할 때마다 올린다. 사이드 패널 맨 아래 `버전 0.2.0`(흐린 글씨).
- 켤 때 한 번, 화면을 막지 않고 뒤에서 `latest.txt`를 받는다(최대 10초). 인터넷 없음·curl 없음·형식 오류·같거나 낮은 버전이면 아무것도 표시하지 않는다.
- 새 버전이면(숫자 비교: 0.10.0 > 0.9.0) 사이드 패널 맨 위에 `새 버전이 있습니다: 0.3.0`과 버튼.
  - 윈도 `업데이트`: 설치 파일을 임시 폴더(`%TEMP%\MixerAnalyzer-Setup.exe`)로 받는 동안 `업데이트 받는 중…`. 다 받으면 설치 파일을 실행하고 앱을 닫는다. 받기 실패 `업데이트를 받지 못했습니다: {오류}`, 실행 실패 `설치 파일을 실행하지 못했습니다: {오류}`(빨간 글씨, 앱은 그대로, 버튼으로 다시 시도).
  - 맥 `받으러 가기`: 드라이브 폴더를 브라우저로 연다. 실패 `드라이브를 열지 못했습니다: {오류}`.
- 윈도에서 curl 창이 깜빡이지 않게 `CREATE_NO_WINDOW`로 부른다.

## 설치 파일 `MixerAnalyzer-Setup.exe`
- 관리자 권한 없이(`RequestExecutionLevel user`) `%LOCALAPPDATA%\Programs\MixerAnalyzer`에 설치. 한국어 화면.
- 화면: 시작(앱이 닫힐 시간도 됨) → 설치 → 끝(`믹서 분석기 실행` 체크).
- 넣는 것: `MixerAnalyzer.exe`, `README.md`, `Pretendard-LICENSE.txt`, 제거 프로그램.
- 시작 메뉴·바탕화면 바로가기 `믹서 분석기`. 설정 → 앱 목록에 `믹서 분석기`(버전 표시)로 등록(HKCU).
- 같은 위치에 다시 설치하면 덮어쓴다(업데이트). 제거는 설치한 파일·바로가기·등록만 지우고 저장한 세팅(`%APPDATA%\MixerAnalyzer`)은 남긴다.
- LZMA 압축으로 10.4MB(브라우저 업로드 한도) 아래.
- 윈도 zip은 더 이상 만들지 않는다.

## 배포 순서
1. `Cargo.toml` 버전을 올리고 빌드(`scripts/build-win.sh`, `scripts/build-mac.sh`). 맥 앱 Info.plist 버전도 Cargo 버전으로 채운다.
2. 드라이브에 설치 파일을 "기존 파일 대체"로 올린다(첫 배포만 새 파일 → 그 ID를 빌드 스크립트에 적음).
3. `dist/latest.txt`를 "기존 파일 대체"로 올린다. 설치 파일보다 먼저 올리면 안 됨(옛 설치 파일을 받게 됨).
- 지금 0.1.0 zip을 쓰는 PC는 확인 기능이 없으니 0.2.0 설치 파일을 한 번 직접 받아 설치한다.
- 드라이브 폴더 링크 권한은 편집자 → 뷰어로 바꾼다(누구나 설치 파일을 바꿔 놓을 수 있으면 자동 설치가 그 파일을 실행함). 사용자 승인함.
