# 수학 검토 후 고칠 것(1·2단계) — 변경 설계

## 의도
전체 코드 수학 검토(리뷰 3 + 재검증 8)에서 확인된 문제 중 엔진 설계를 바꾸지 않는 것만 고친다. 엔진 재설계(MID 절대 추천, 누적 부스트 한도, 한도 안 주파수 고르기, 63·80 Hz 맞춤)와 하울링 감지는 다음 단계(설계 따로).

## 1단계: 작고 확실한 것
1. **대역 경계 빈**(`spectrum.rs` `band_db`): FFT 칸 k의 폭 [(k−½)·bw, (k+½)·bw] 중 [lo, hi)에 든 비율만큼 그 칸 파워를 더한다(지금은 중심이 들면 전부, 아니면 0). 63–125 Hz가 샘플레이트에 따라 ±1 dB 흔들리던 것이 사라진다. 문서 주석도 고친다. 기존 테스트는 그대로 통과해야 한다(재검증에서 114개 통과 확인).
2. **저장 파일에 샘플레이트**(`saved.rs`, `app.rs`): 줄 끝에 30번째 필드로 샘플레이트(Hz 정수)를 쓴다. 29필드 줄(0.3.1 이하)도 읽고 `sample_rate: None`(이전 방식으로 잰 소리)으로 둔다. 복구 모드 노트:
   - `None`: `이 소리는 이전 버전에서 저장해 저음 쪽 값이 조금 다릅니다. 같은 마이크·채널로 다시 저장해 주세요.`
   - 지금 분석의 샘플레이트와 다름: `저장할 때와 샘플레이트가 다릅니다(저장 48kHz, 지금 44.1kHz). 같은 입력장치 설정에서 분석해야 정확합니다.` (kHz는 소수 첫째 자리까지, .0은 뺌)
   - 0.3.1은 30필드 줄을 못 읽고 다시 쓸 때 지운다 → README에 "저장 폴더를 여러 PC가 함께 쓰면 모두 0.3.2 이상으로" 한 줄.
3. **저장 파일 줄 보호**(`saved.rs`, `app.rs`): 읽을 때 첫 줄 BOM을 떼고, 빈 줄은 무시한다. 읽지 못한 줄이 하나라도 있으면 읽은 소리는 그대로 쓰되 쓰기를 막고(`write_blocked`) 빨간 글로 알린다: `saved.tsv의 {n}번째 줄을 읽지 못했습니다. 파일을 고치거나 [읽기]/[쓰기]로 다른 파일을 고르기 전에는 저장·삭제하지 않습니다.` (여러 줄이면 첫 줄 번호)
4. **대역 가드 구멍**(`advice.rs`): 노브 중심을 대역 비교 구간에서 찾을 때 `centre.max(80.0)`(첫 구간 하한)으로 찾는다. Soundcraft Signature LOW 60 Hz가 웅웅거림 구간을 따르게 된다. 테스트: 웅웅거림이 빨간 Signature 12 화면값에서 LOW를 올리지 않음(보통·복구 모드).
5. **좁은 평활**(`spectrum.rs` `display_db`): `smooth_n`을 `per_oct / 2` 이하로 줄인다(평활 창이 다음 점까지 닿게; 0은 그대로 없음). README에 "해상도보다 좁은 평활은 해상도에 맞춰 넓힘" 한 줄. 테스트: 1/12 해상도 + 1/24 평활에서 두 점 사이 톤이 사라지지 않음.
6. **낮은 샘플레이트 거부**(`app.rs` `advise`): 분석 샘플레이트가 40 kHz 미만이면 노브는 이름만 두고(돌리기 없음) 노트 하나: `입력 샘플레이트가 {x}kHz라 16kHz 대역까지 잴 수 없습니다. 믹서 USB 입력(44.1kHz 이상)을 고르세요.` 그래프는 그대로.
7. **업데이트 다운로드는 https만**(`update.rs` `curl`): `--proto =https --proto-redir =https`. 무시된 네트워크 테스트(`drive_latest_parses`)로 실제 Drive 주소가 여전히 받아지는지 확인.

## 하지 않는 것
엔진 재설계, 하울링, 버전 비교 강화(릴리스 스크립트가 잘못된 버전을 만들 수 없음), 그래프 마우스 표시, 데모 과부하, NaN 샘플(cpal에서 안 옴), 이름 정리.

## 확인
`cargo test` 전체 통과 + 위 새 테스트. 저장 파일: 29필드·30필드·BOM·깨진 줄 읽기 테스트, 30필드 왕복. 믹서: 기존 프로필 테스트(이름 중복 없음 등) 통과.

## 배포
main에 머지. 버전 올림·빌드·드라이브 업로드는 따로 묻는다.
