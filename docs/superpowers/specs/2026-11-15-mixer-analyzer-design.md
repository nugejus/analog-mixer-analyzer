# 믹서 분석기 (mixer-analyzer) 설계

## 의도
교회 방송팀은 아날로그 믹서만 가지고 있습니다. 지금 들어오는 소리의 주파수 분포가 어떤지, 어떻게 고쳐야 좋은지 볼 방법이 없습니다. 믹서 출력은 PC로 들어갑니다. 이 프로그램은 그 입력을 실시간으로 분석합니다. 예배 전 사운드체크 때 **마이크를 하나씩** 맞추면서 아래를 보여줍니다.
- 지금 소리의 주파수 그래프
- 디스토션(클리핑, 과부하, 하울링) 여부
- 선택한 믹서에 실제로 있는 노브만 골라 "어느 방향으로 몇 도" 돌릴지 (예: "HIGH 반시계 15°")

사용자는 전문 엔지니어가 아닌 봉사자입니다. 그래서 화면 문구는 모두 쉬운 한국어로 씁니다.

## 목표
- 실시간 스펙트럼(20 Hz–20 kHz, 로그 축). 현재 소리, 피크 홀드, 목표 곡선을 함께 그립니다.
- 레벨/디스토션 기록(최근 30초). 클리핑 지점, 과부하 의심, 하울링 표시를 넣습니다.
- 상대 추천. 노브가 지금 어디 있는지는 모릅니다. 그래서 "지금 위치에서 어느 방향으로 몇 도"만 알려줍니다. 목표에 가까워지면 "✓".
- 주요 아날로그 믹서 목록을 넣습니다. 믹서와 채널 그룹에 따라 실제로 있는 노브 종류만 보여줍니다.
- macOS(.app, 유니버설)와 Windows(.exe) 빌드를 만듭니다.

## 하지 않는 것
- 노브의 절대 위치 추정, 캘리브레이션 마법사, dBu 환산.
- 여러 마이크 동시 분석. 믹서 USB는 메인 믹스만 보내므로 한 번에 한 채널만 분석합니다.
- 디지털 믹서(Yamaha MGX 등) 제어나 원격 연결.
- 녹음, 파일 분석, 설정 저장.

## 실패로 보는 것 (기술적으로 돌아가도)
- 화살표가 계속 깜빡여서 따라 돌릴 수 없는 경우.
- 무음이나 권한 거부 상태에서 엉뚱한 추천이 나오는 경우.
- 고른 믹서에 없는 노브를 추천하는 경우.

## 제약
- 언어: Rust 1.96.0. `rust-toolchain.toml`로 고정합니다. 이 프로젝트에서 venv에 해당하는 것이 이 파일입니다.
- 의존성은 정확한 버전으로 고정합니다: eframe =0.37.0, egui_plot =0.38.0, cpal =0.18.2 (0.19는 API가 깨짐), realfft =3.5.1, rtrb =0.4.1. 이 밖의 새 의존성은 추가하지 않습니다.
- 믹서 프로필은 **팩토리 패턴**으로 만듭니다(사용자 요구). `MixerFactory::create(MixerModel) -> MixerProfile`.
- UI 디자인 자원은 인터넷에서 받아 씁니다(fetch는 허락받음).
  - Catppuccin Mocha 팔레트 (MIT, palette v1.8.0). 값을 코드에 넣고 출처와 MIT 표기를 남깁니다.
  - Pretendard Regular v1.3.9 (OFL). `assets/`에 넣고 바이너리에 내장합니다.
- Windows: `cargo xwin`, `+crt-static`, 콘솔 창 숨김.
- macOS: Info.plist에 `NSMicrophoneUsageDescription`을 넣고 ad-hoc codesign 합니다. 공증은 하지 않으므로 처음 열 때 "확인 없이 열기"가 필요합니다.
- 커밋 메시지는 제목 한 줄만 씁니다. 본문과 Co-Authored-By는 넣지 않습니다.

## 접근 방식
| 안 | 내용 | 장단점 |
|---|---|---|
| **A. egui/eframe 네이티브 (선택)** | 즉시 모드 GUI, wgpu 렌더러, egui_plot | 단일 실행 파일(Windows 15.9MB)입니다. 연구 단계에서 만든 프로브가 mac과 Windows 둘 다에서 이미 컴파일되었습니다. 그래프를 다시 그리는 비용이 낮습니다. 대신 위젯이 투박해서 노브는 직접 그립니다. |
| B. Tauri + 웹 UI | Rust 백엔드 + HTML/JS 차트 | 화면을 예쁘게 만들기 쉽습니다. 하지만 Windows WebView2 의존성이 생기고, 언어가 둘이 되며, 오디오→웹뷰 IPC 비용이 듭니다. |
| C. iced / Slint | Rust 선언형 GUI | 실시간 플롯 위젯이 부족해서 직접 만들어야 하고, 검증된 경로가 없습니다. |

A는 제 판단입니다. 사용자가 구현 방법을 맡겼고, 프로브로 이미 검증된 경로입니다. egui-phosphor 아이콘은 egui 0.36이 필요해서 버전이 충돌합니다. 그래서 쓰지 않고 화살표는 Painter로 직접 그립니다.

## 신호 경로와 믹서별 연결 (화면 하단 팁으로 표시)
- Mackie ProFX(전 세대): USB는 메인 믹스만 PC로 보냅니다. PFL은 USB로 가지 않습니다. 그래서 맞출 채널만 올리고 나머지 채널과 FX는 내립니다.
- Yamaha MGP X: PC로 가는 USB 오디오가 없습니다. 오디오 인터페이스가 필요합니다. 맞출 채널의 PFL을 켜고 MONITOR OUT(L)을 인터페이스에 연결합니다. MONITOR 노브는 한 위치에 고정합니다. PFL 신호는 HPF/COMP/EQ를 지난 뒤, ON/페이더 앞에서 나옵니다.
- 문구 원문은 아래 "믹서 데이터" 표의 팁 열을 따릅니다.

## 분석 (DSP)
- **입력:** cpal 기본 입력 설정을 씁니다. 샘플 형식(F32/I16/I32 등)은 f32로 변환합니다. 콜백은 인터리브 샘플을 rtrb 링(용량 = sr×ch×2초)에 넣기만 합니다. 링이 차면 샘플을 버립니다. 분석은 UI 스레드에서 합니다(프레임마다 링을 비움).
- **분석 채널:** 선택식입니다(1=L 기본, 2=R). 장치가 1채널이면 0번 채널을 씁니다. 클리핑 검출만 모든 채널을 대상으로 합니다.
- **FFT:** 8192점 Hann, hop 4096(50%). 샘플레이트와 상관없이 같습니다. 빈 전력 P_k = 2|X_k|² / (N·Σw²)입니다(DC와 나이퀴스트는 ×1). 그러면 ΣP_k가 평균 제곱이 되어, 풀스케일 사인이 −3.01 dB로 읽힙니다.
- **밴드:** 1/3옥타브 25개, 63 Hz–16 kHz(Byrne 표와 같은 중심 주파수). 밴드 경계는 fc·2^(±1/6), 밴드 전력은 경계 안 빈들의 ΣP_k입니다. 값이 비면 바닥값 −150 dB를 씁니다.
- **표시 곡선:** 20 Hz–20 kHz 1/6옥타브 점이고, 점 폭은 ±1/12옥타브입니다. 빈이 없는 저역 점은 가장 가까운 빈을 씁니다. 평활은 전력 지수평균(τ=0.3초)입니다. 피크 홀드는 1.5초 유지한 뒤 12 dB/s로 떨어집니다. Y축은 −90…0 dB입니다.
- **활성 음성 판정:** 프레임(hop) RMS가 −60 dBFS보다 크고 잡음 바닥+12 dB보다 크면 "활성"입니다. 잡음 바닥은 최근 10초 프레임 RMS의 최솟값입니다.
- **장기 평균(추천 근거):** 최근 4초 안의 활성 프레임으로 밴드 전력을 평균합니다. 활성 시간이 1.5초 미만이면 추천 없이 "말씀을 계속해 주세요"를 띄웁니다.
- **요약값:** 활성 구간 피크(dBFS), RMS(전력 평균), SNR(RMS − 잡음 바닥), 다이내믹 레인지(활성 프레임 RMS의 90퍼센타일 − 10퍼센타일), 크레스트(피크 − RMS).
- **클리핑:** 채널별로 |x| ≥ 0.999인 샘플이 3개 이상 연속되면 1회로 셉니다. 누적 횟수는 리셋 버튼을 누를 때까지 유지합니다.
- **레벨 기록:** 100 ms마다 (최대 샘플 피크 dB, 그 사이 클리핑 여부)를 남기고 300개(30초)를 유지합니다.
- **과부하 의심:** 크레스트 < 9 dB이고 피크 > −20 dBFS. 아날로그 단에서 눌리거나 COMP가 과한 경우입니다.
- **하울링 의심:** 프레임마다 100 Hz–10 kHz에서 가장 큰 빈 k를 찾고 아래를 모두 봅니다.
  - PNPR: P_k − mean(P[k±4..=k±12]) ≥ 15 dB
  - PHPR: P_k − max(P[2k±1], P[3k±1]) ≥ 20 dB (범위 밖이면 통과)
  - P_k > −60 dB
  - 같은 k(±2빈)가 6프레임 연속이고, 프레임 사이 변화가 ≤ 2 dB

  모두 맞으면 해당 주파수를 보고합니다. 조건이 6프레임 연속 깨지면 해제합니다.
- **무입력:** 최근 3초 동안 |x|가 1e-7 미만이면 "입력 신호가 없습니다"를 띄웁니다. macOS에서는 마이크 권한이 꺼져 있어도 무음으로 들어오기 때문입니다.
- 생략: True peak(4× 오버샘플링). 샘플 피크만으로 사운드체크에는 충분합니다. 방송 인코딩에서 inter-sample 오버가 문제가 되면 추가합니다.

## 추천 엔진
- 편차 d_b = 측정 장기평균_b − 목표_b. 비교는 100 Hz–12.5 kHz의 22개 밴드만 씁니다. 가중치는 100 Hz–10 kHz가 1.0, 12.5 kHz가 0.5입니다. 63/80 Hz는 저역 컷 판단에만 씁니다.
- 각 노브의 응답 모양 R(f)는 노브 1 dB당 dB 변화입니다.
  - LOW 셸프: 1/(1+(f/fc)²)
  - HIGH 셸프: 1/(1+(fc/f)²)
  - MID 벨: exp(−(log2(f/fc))²/(2·0.6²))
- 미지수는 [c(전체 레벨, 노브 아님), g_1..g_n(EQ 노브)]입니다. 최소화하는 식은 Σ w_b(−d_b − c − Σ g_k R_k(f_b))² + 0.01·Σ g_k²이고, 정규방정식을 가우스 소거로 풉니다.
- 각 g는 ±15 dB로 제한합니다. 단 LOW 부스트는 최대 +3 dB입니다(근접효과와 험 방지).
- MID 주파수 스윕 노브의 후보 주파수는 범위 안의 1/3옥타브 중심들입니다. 스윕 MID가 둘이면 좌표 하강을 2회 돌립니다. 잔차가 가장 작은 후보를 고르고, 이전 추천 주파수의 잔차보다 20% 이상 좋을 때만 바꿉니다(히스테리시스).
- 표시 규칙
  - |g| < 1.5 dB이면 "✓". ✓ 상태는 |g| > 2.5 dB가 되어야 풀립니다.
  - 그 밖에는 회전입니다. 각도 = g × 10°/dB(300° 회전에 ±15 dB)이고 5° 단위로 반올림합니다. g > 0이면 시계방향입니다.
- FREQ 노브: 짝인 MID가 ✓이면 "✓ 그대로", 아니면 "FREQ ○○Hz 눈금에".
- 저역 컷 스위치: c0 = 250 Hz–4 kHz 편차의 평균이라 할 때, mean(d_63, d_80) − c0 > +3 dB이면 "켜기 권장", 아니면 "✓".
- GAIN
  - 최근 4초 사이에 클리핑이 있었거나 활성 피크 > −6 dBFS면 피크가 −12 dBFS가 되도록 내립니다(최소 3 dB).
  - 활성 피크 < −24 dBFS면 −12 dBFS가 되도록 올립니다(최대 20 dB).
  - 그 밖에는 ✓입니다.
  - 각도 = dB × 300°/게인 범위(dB)입니다. 시계방향이 증가입니다(Yamaha MGP도 같음).
- COMP(있는 그룹만): 다이내믹 레인지 > 18 dB이면 시계 30°, 크레스트 < 9 dB이면 반시계 30°, 그 밖에는 ✓입니다.
- 안내 문구
  - SNR < 30 dB: "주변 잡음이 큽니다(SNR ○○dB). GAIN보다 마이크를 입에 더 가깝게 하세요."
  - 과부하 의심, 하울링 의심(○○Hz: 마이크와 스피커 거리 확인, FREQ를 해당 눈금에 두고 MID를 줄이세요), 무입력.
- 추천은 0.5초마다 다시 계산합니다. 믹서나 채널 그룹을 바꾸면 엔진 상태를 초기화합니다.
- 각도는 "느낌" 정도의 정확도입니다. 실제 노브의 dB 눈금은 선형이 아닙니다.

## 믹서 데이터 (마이크 입력이 있는 채널 그룹만)
EQ ±15 dB(300°)는 모든 믹서에 공통입니다. "게인"은 게인 노브 전체 범위(dB)입니다. MID가 "a–b"면 스윕이고 숫자 하나면 고정입니다.

- MACKIE_USB: "USB로는 메인 믹스만 PC에 갑니다(PFL은 안 감). 맞출 채널만 올리고 다른 채널과 FX는 내리세요. 채널 페이더는 U(0dB)에 두세요."
- YAMAHA_MGP: "이 믹서는 PC로 가는 USB 오디오가 없습니다. 오디오 인터페이스가 필요합니다. 맞출 채널의 PFL을 켜고 MONITOR OUT L을 인터페이스에 연결하세요. MONITOR 노브는 한 위치에 고정하세요."
- YAMAHA_XU: "USB로는 STEREO 버스(채널 페이더 이후)가 갑니다. 맞출 채널만 ST로 보내고 다른 채널은 끄세요. 채널 페이더는 0dB에 두세요."
- BEHRINGER_USB: "USB로는 메인 믹스가 갑니다. 맞출 채널만 올리고 다른 채널과 FX는 내리세요."
- SOUNDCRAFT_USB: "USB SEND를 MST로 두면 메인 믹스가 갑니다. 맞출 채널만 올리고 다른 채널은 내리세요."
- AH_USB: "USB 출력 선택 스위치를 모두 해제하면 메인 L-R이 갑니다. 맞출 채널만 올리고 다른 채널은 내리세요."
- NO_USB_SOLO: "이 믹서는 USB가 없습니다. 맞출 채널을 SOLO/PFL하고 CONTROL ROOM(또는 PHONES) 출력을 오디오 인터페이스로 PC에 연결하세요."

신뢰도 "중간"인 값(문서끼리 다름)은 코드 주석에 표시합니다: Behringer 저역컷 75/80 Hz, Soundcraft Signature 게인 범위, EPM LOW 60/80 Hz, ZEDi 게인, MGP12X HPF 유무. Soundcraft Signature의 리미터 버튼은 추천하지 않습니다(YAGNI).

## 빌드와 배포
- `scripts/build-mac.sh`
  - aarch64와 x86_64로 릴리스 빌드한 뒤 lipo로 유니버설 바이너리를 만듭니다.
  - `dist/MixerAnalyzer.app`을 만듭니다. Info.plist에는 NSMicrophoneUsageDescription(한국어)과 CFBundleIdentifier `org.church.mixer-analyzer`를 넣습니다.
  - ad-hoc 서명하고 `dist/MixerAnalyzer-mac.zip`으로 묶습니다(ditto).
- `scripts/build-win.sh`: cargo xwin으로 빌드해서 `dist/MixerAnalyzer-win.zip`을 만듭니다(exe와 README).
- README.md(한국어)에 들어갈 내용: 설치, 첫 실행(Gatekeeper, 마이크 권한), 믹서별 연결, 화면 읽는 법.
- 업로드: Google Drive 폴더 "mixer-analyzer"에 Claude in Chrome으로 올립니다(Drive MCP는 10MB 제한).
